# Lessons learned: Chat-analytics

Журнал граблей и архитектурных выводов проекта. Пополняется по мере работы с данными.

- **2026-10-21 (Data Audit)**: Исходные Telegram JSON выгрузки содержат числовой `from_id` в 99.8% сообщений (сквозной Telegram ID). Username часто опущен в теле сообщения и доступен только в профиле. 2.9% ядра участников генерируют 45.4% контента.
- **2026-10-21 (LAYA VRAM & API)**: Библиотека `laya` (0.4.12) поддерживает только типы `choice`, `noul`, `score`. Большие батчи (>128) забивают 12GB VRAM и вызывают медленный PCIe swapping. Оптимальный режим: `batch_size=64`, ограничение длины текста до 200 символов, `torch.cuda.empty_cache()` между батчами — стабильные 28 сообщений/сек при потреблении 4.7 GB VRAM.
- **2026-10-21 (Product Insights vs Reactions)**: Сортировка цитат только по количеству реакций (`reactions_count DESC`) выдает закрепленные сообщения модераторов и ботов-посредников. Для реальных болей необходима фильтрация ботов и приоритизация маркеров сомнений и вопросов (`?`, `не могу`, `отказ`, `подскажите`) в недавнем временном окне.
- **2026-10-21 (DuckDB Concurrency)**: DuckDB блокирует файл БД при операциях записи. В веб-приложении FastAPI все GET-запросы должны строго открывать соединение в режиме `read_only=True`, а операции записи — изолироваться в короткие транзакции (<50ms).
